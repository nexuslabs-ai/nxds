Edit a single line of text in place. The value reads as text until you open the editor, then saves with Enter or Save.

## When to use it

Use it for one field on a detail view, such as a name or title, where a whole form would be heavy. For several related fields, or anything longer than one line, use a form with Field and Input.

## Value and changes

`value` is controlled: pass the saved value and update it in `onCommit`.

- Enter or Save emits the trimmed draft through `onCommit`. Escape and Cancel emit nothing.
- Return a promise from `onCommit` to keep the editor open until it settles. Resolving closes the editor; rejecting, or throwing, keeps the draft open so you can show `error` and the user can retry.
- While a save is pending the input is read-only and Escape, Cancel and leaving the editor do nothing.
- `required` blocks an empty save and shows `requiredMessage` until the user types.

The block owns the draft and, unless you pass `editing`, whether the editor is open. Your application owns the saved value, persistence and any save error.

## States and dismissal

`blurBehavior` decides what happens when focus leaves the whole editor: keep it open (the default), save, or cancel. Closing returns focus to the edit trigger only when focus was still inside the editor, so it never takes focus from the next control. A controlled close while a save is pending discards that save's result.
